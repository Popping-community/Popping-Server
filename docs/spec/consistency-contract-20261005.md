# Popping 데이터 일관성 기준 (2026-10-05)

상태: **합의 (사용자 결정 2026-10-05)**. 기준 환경은 로컬 앱 2대 구성(HAProxy roundrobin, Redis, MySQL Primary/Replica)이다.
용도: 캐시·중계·유실 허용 같은 설계 판단을 기능마다 새로 정하지 않고, 이 표의 어느 칸에 해당하는지로 정한다.

---

## 1. 판단 기준 — "틀렸을 때 누가, 얼마나 곤란한가"

| 등급 | 어긋나면 | 허용 한계 |
|---|---|---|
| **A. 본인 행동의 결과** | "내가 쓴 글·댓글·좋아요가 안 보인다" → 버그로 느끼고 다시 누르거나 중복 작성 | **즉시** |
| **B. 삭제·권한·보안** | 지운 글이 보임, 권한 없는 수정, 인증 우회 | **즉시, 서버 간 차이 없음** |
| **C. 남의 행동이 보이는 시점** | 남의 좋아요·댓글이 늦게 보임 | **보통 1초 이내, 최악 30초** |
| **D. 집계 숫자** | 조회수 등이 잠깐 또는 소량 어긋남 | **근사치 허용, 최종적으로 맞으면 됨. 조회수는 비정상 종료 시 일부 유실 허용** |

## 3. 이 기준으로 내린 결정 (기록)

| 결정 | 기준 |
|---|---|
| 게시판 첫 페이지 캐시 제거 (#160) | 글쓴이 본인(A)까지 최대 5분 어긋남. 아끼는 비용은 쿼리 1개 |
| 댓글 캐시 유지, 전파 없음 | 본인(A)은 우회로 즉시, 남(C)은 최대 5초 — 기준 안 |
| 상세 캐시 OFF 유지 | 삭제·수정(B)이 다른 서버에서 최대 30분 노출 |
| 좋아요 Redis 중계 + 재조회 (U2) | 남의 좋아요(C)가 다른 서버에선 새로고침 전까지 안 보임 → 기준 초과였음 |
| Streams·Outbox·Kafka 미도입 | C·D 등급은 최대 1회 전달 + 재조회로 충분 |
