## 3. 이 기준으로 내린 결정 (기록)

| 결정 | 기준 |
|---|---|
| 게시판 첫 페이지 캐시 제거 (#160) | 글쓴이 본인(A)까지 최대 5분 어긋남. 아끼는 비용은 쿼리 1개 |
| 댓글 캐시 유지, 전파 없음 | 본인(A)은 우회로 즉시, 남(C)은 최대 5초 — 기준 안 |
| 상세 캐시 OFF 유지 | 삭제·수정(B)이 다른 서버에서 최대 30분 노출 |
| 좋아요 Redis 중계 + 재조회 (U2) | 남의 좋아요(C)가 다른 서버에선 새로고침 전까지 안 보임 → 기준 초과였음 |
| Streams·Outbox·Kafka 미도입 | C·D 등급은 최대 1회 전달 + 재조회로 충분 |

## 5. Redis 장애 시 보장 범위 (2026-10-05 관찰, 사용자 결정: 허용으로 명시)

Redis는 세션 저장소와 좋아요 중계 채널을 맡는다. 영속화 OFF(`--save ""`, `--appendonly no`).

| 기능 | Redis 중지 동안 | Redis 복구 후 |
|---|---|---|
| 비로그인 조회(목록·상세·댓글), 게스트 글쓰기·삭제 | 정상 | 정상 |
| 좋아요 | 요청 성공, 같은 서버 시청자에게 전달. 다른 서버 중계는 실패(지표 `like.relay.publish{result=failed}`). 화면은 다음 재조회(설계상 30초 주기)에서 맞춰짐 — 이 경로는 측정하지 않음 | 재구독 후 중계 재개. 8초 시점 1/2, 그 뒤 2/2 확인(정확한 시간 미측정) |
| 회원 요청·로그인, 게스트 글 수정 | **불가** — 6~8초 안에 500 (제한시간 2초 적용 후. 이전엔 클라이언트 제한 70초까지 응답 없음). 요청당 2초보다 긴 이유는 미확정 | 복구 직후 확인은 실패했고, Lettuce 재연결 로그 뒤 수동 확인에서 정상(복구까지 걸린 시간은 미측정. Lettuce 기본 재연결 간격은 지수 증가, 최대 30초). **기존 로그인은 풀림**(세션 소실) |

- 세션 요청이 멈추면 Tomcat 스레드를 잡아 Redis와 무관한 비로그인 조회까지 막을 수 있어, Redis 명령 제한시간을 60초 → 2초(연결 1초)로 줄였다. 스레드 고갈 자체는 재현하지 않았다(순차 요청 관찰).
- 원자료: `.claude/docs/research/redis-outage-20261005/` (`redis-outage.json` 기본값, `redis-outage-2s-timeout.json` 적용 후).
